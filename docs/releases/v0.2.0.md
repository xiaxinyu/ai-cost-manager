# Release v0.2.0 — OpEx Statement & Reference Architecture

**Date:** 2026-07-08  
**Tag:** `v0.2.0`  
**Status:** UI and reporting milestone — unified OpEx statement layers, Ref. Arch · Tariff terminology, and multi-project report polish on top of v0.1.0 billing ingest.

---

## Summary

v0.2.0 reframes the product around a single **OpEx statement** narrative: invoice actuals first, optional meter/platform composition, then a clearly bounded **Reference architecture** benchmark (not invoice spend), and token **consumption drivers**. Cost, Reports, and Tokens share the same pill labels, table headers, and chart legends. Reports gains segment-aware daily cost lines, a redesigned Consumption section, and a structured Detail ledger.

---

## Highlights

### OpEx statement model

- **Layered Summary** on Cost and Reports:
  1. **Actual billing** — OpEx Total, avg/day, billed days, period
  2. **Actual billing · composition** — OpEx · Meter, OpEx · Platform, meter share (single-row layout, no grid gap)
  3. **Reference architecture** — Ref. Arch · Tariff, tariff variance, tariff schedule (`Not invoice` badge)
  4. **Consumption drivers** — imported token volume (Reports Summary when token CSV exists)
- Central semantics in `app/static/js/cost-semantics.js` — pills, legends, billing keys, chart dataset labels.
- Finance doc updated: `docs/finance-statement-model.md`.

### Terminology (breaking UI labels only)

| v0.1.0 | v0.2.0 |
|--------|--------|
| Market / Market benchmark | **Ref. Arch · Tariff** |
| Reference (nav) | **Ref. Arch.** |
| Tariff reference (sections) | **Reference architecture** |
| Actual (some table headers) | **OpEx** / **OpEx · Meter** |

Insights cards, chart footnotes, and Import / Prices lineage copy use the same naming. **No API or schema field renames** — `catalog_cost_usd` and internal `market` aliases remain for compatibility.

### Cost (single project)

- **Daily spend** chart: Total + segment lines (by Azure resource when one project is in scope; by project name on Reports).
- Legend aligned with Allocation → By model table rows (Meter / Platform / Ref. Arch · Tariff).
- **By model** Input/Output charts use stacked bars; clearer segment legend pills.
- **Reference architecture** subzone inside OpEx Statement with tariff variance footnote (`OpEx − Ref. Arch · Tariff`).
- **Subproject cost strip** — segment cards by Azure resource when subprojects exist.
- **7-day cost forecast chart removed** — billing signal was too noisy; run rate stays Actual-only.

### Reports (multi-project)

- **OpEx Statement** matches Cost layer structure and styling.
- **Run Rate** — daily cost with Total + segment series (same API as Cost); monthly cost unchanged.
- **Consumption** — summary meta bar; separate Input / Output run-rate charts; collapsible out/in ratio chart; monthly usage table removed.
- **Detail ledger** — dedicated section with insight chips, share bars, and softer table styling (replaces nested `<details>` blocks).
- **By model** — executive chart cards, custom model legend pills, OpEx vs Ref. Arch · Tariff daily comparison footer key.
- **By project** — meter vs platform columns when meter data exists.

### Tokens

- **Subproject IN/OUT segment strip** — fixed visibility after DOM insert; shows nested `token/<subproject>/` breakdown.
- Unit economics table headers: **Ref. Arch · Tariff** vs effective OpEx rate.
- Shared subproject strip CSS with Cost page.

### Pricing & Import

- **Model prices** and **Price sources** — page-root styling, header gradients, aligned with dashboard shell.
- Import lineage note: billing → OpEx · tokens → Volume · price sync → Ref. Arch. tariff schedule.

### Backend & tests

- `get_financial_daily_cost_by_segment()` — daily cost series split by Azure resource (single project) or project name (multi-project); exposed as `daily_by_segment` in financial stats / reports API.
- Insights copy updated for Ref. Arch · Tariff variance and unpriced models.
- **130 passed, 1 skipped** (`pytest --ignore=tests/e2e` at release cut).

## Known limitations

- **Ref. Arch · Tariff** still requires Model Prices catalog + token/billing bridge; token-only projects show volume without meter cost or tariff totals.
- **Segment daily lines** depend on resource/project attribution in billing data; sparse or unmatched rows may yield fewer segments.
- **7-day billing forecast** not shown in UI by design; use external tooling if long-range projection is needed.
- Insights API may return cards; Cost/Reports do not render insight panels in the main layout (same as v0.1.0).
- Single-user session auth; no RBAC in v0.2.0.
