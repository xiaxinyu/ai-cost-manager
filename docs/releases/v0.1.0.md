# Release v0.1.0 — Models Cost Management

**Date:** 2026-07-08  
**Tag:** `v0.1.0`  
**Status:** First public milestone — billing ingest, cost analytics, token usage, and multi-project reporting in one local-first web app.

---

## Summary

v0.1.0 delivers an end-to-end workflow for Azure OpenAI–style billing: import CSVs from `bills/`, store them in SQLite, and explore spend through **Cost**, **Reports**, **Tokens**, and **Model prices** pages. Layouts follow a finance-style flow (**Scope → Summary → Trends → Allocation**) so totals, trends, and breakdowns read like a small statement rather than a dashboard of unrelated widgets.

---

## Highlights

### Billing & data integrity

- **CSV ingest** from `bills/<project>/` with checksum tracking and optional re-import (`ingest`, Import page, `--reimport-force`).
- **Same-day row merge fix**: when Azure exports Actual + forecast rows for one date, Actual `CostUSD` is no longer wiped by empty follow-up rows.
- **Subproject layout**: nested paths `bills/<project>/token/<subproject>/` and matching billing discovery; subproject filter on Cost / Tokens / Import.
- **Authoritative totals**: project and report summaries use SQL `SUM(cost_usd)` aligned with billed-days logic.

### Cost (single project)

- **Reporting scope** filter: project, subproject, date range.
- **Summary**: Actual total, avg/day, billed days, period; optional **Market benchmark** row (Meter / Variance / list price).
- **Trends**: daily Actual spend chart.
- **Allocation**: by model, by Azure resource, line items — in one section with internal nav.
- Cross-page “All projects” table removed (lives on Reports only).

### Reports (multi-project)

- **Summary** with billing KPIs, optional benchmark and imported-token volume rows.
- **Trends**: daily and monthly Actual billing.
- **By project** (step 3): daily average billing + token share per project.
- **By model** (step 4): meter vs Market when catalog data exists.
- **Tokens** and **Detail** sections for volume trends and paginated daily/monthly tables.
- No Insights cards; no `Cost →` drill links between pages.

### Tokens

- Grafana **token** and **performance** CSV import; volume, cache, latency panels.
- Finance layout: **Summary → Trends → Performance → Allocation** (by model, unit price).
- Subproject-scoped metrics and model breakdown.

### Pricing

- **Model prices**: compact catalog table with filters, pivot/compact views, retail sync dialog.
- **Price sources**: single-table editor for reference/API URLs (duplicate Reference block removed).

### Platform

- FastAPI + SQLite, session auth, CLI (`ingest`, `serve`, `create-admin`).
- Chart.js bundled locally; date-range picker shared across pages.
- **pytest** suite (unit + API); optional **Playwright** e2e (`pytest -m e2e`).

## Upgrade & deploy notes

| Item | Notes |
|------|--------|
| **Database** | Schema migrations run on startup. Existing DBs upgrade in place; back up `data/cost_mgmt.sqlite3` before first v0.1.0 boot. |
| **Re-import billing** | After upgrading, run a full re-import if you previously saw low totals on same-day Azure rows: `python -m app.cli ingest --bills-dir bills --db-path data/cost_mgmt.sqlite3 --reimport-force` |
| **Auth** | Default auth on. Set `COST_MGMT_SESSION_SECRET_KEY` in production; use `COST_MGMT_AUTH_ENABLED=0` only for local debug. |
| **Auto ingest** | `AUTO_INGEST=0` by default — prefer explicit `ingest` or Import page. |

## Verification (release checklist)

```bash
.venv/bin/python -m pytest --ignore=tests/e2e
.venv/bin/python -m app.cli ingest --bills-dir bills --db-path data/cost_mgmt.sqlite3
.venv/bin/python -m app.cli serve --bills-dir bills --db-path data/cost_mgmt.sqlite3 --host 127.0.0.1 --port 8000
```

Smoke paths:

- `/` — Cost: Summary KPIs, daily chart, allocation tables load for a project with billing.
- `/reports` — Load report: Summary, Trends, By project table populated.
- `/tokens` — Load data for a project with `bills/<project>/token/` CSVs.
- `/import` — Missing files list and import selected.
- `/prices` — Query returns catalog rows after sync or seed.

## Known limitations

- **Forecast** billing is ingested but not emphasized in UI (Actual-first reporting).
- **Insights** API fields may still be returned; UI panels removed on Cost/Reports.
- **Market** benchmark requires Model prices catalog + token/billing bridge; token-only projects show volume without meter cost.
- Single-user session auth; no RBAC or multi-tenant isolation in v0.1.0.
